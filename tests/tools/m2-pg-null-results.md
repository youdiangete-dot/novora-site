# M2 targeted non-null compatibility check

Local-only test of SQL draft SHA-256 `ce8e55a28cbefe42c5f3709062928b35bf026db9b56a43feea8f830bab966495` on PostgreSQL 17.11, using a fresh synthetic database in the previously isolated and subsequently stopped container. The fixture models selected catalog-confirmed constraints, not the complete real Supabase schema or triggers.

17 targeted checks passed: four actual payload-validator assertions, four actual adapter-mapping assertions, eight PostgreSQL RPC/atomicity/null assertions, and one additional PostgreSQL SQL NULL assertion. The SQL generator now includes the equivalent ninth PostgreSQL assertion for future reproduction. Complete valid input created a Brief, contact and receipt. Missing name or email was rejected by the actual validator; when sent directly to RPC, each failed the database constraint and rolled back all three tables. The adapter always sends a `summary_items` property: when absent in the input it sends JSON `null`, which is a non-SQL-null JSONB value and satisfies NOT NULL. A missing RPC key returns SQL NULL and rolls back. This does not establish that downstream consumers accept JSON null as an array.

Reproduction in a separately authorized synthetic PostgreSQL instance: ensure existing synthetic `anon`, `authenticated`, and `service_role` roles; run `m2-pg-null-schema.sql` in a new empty synthetic database, then the exact draft SQL. Run `node tests/tools/m2-pg-null-mapping.cjs <synthetic-output.sql>` from the repository root; copy only the generated nonsecret synthetic file to the disconnected test database and execute it with psql `ON_ERROR_STOP=1`. Do not point this fixture at a live or populated database. Stop and inspect only the container created or approved for the test.

No product source or draft SQL was changed. Actual schema beyond these constraints, triggers, production bindings, backup/retention, and migration/rollback remain independently unverified. Before any separately approved live change preserve receipts and reconcile in-flight submissions; do not drop mappings after traffic without a plan. No customer data, online SQL, deployment or provider call was used.
