# NOVORA Agent 53C Pure Helper And Fake Fixture Test Plan

## 1. Purpose And Role

Agent 53C is a docs-only plan for a future pure-helper and fake-fixture test
layer around the internal AI sketch draft pipeline.

Agent 53C is:

- Internal planning only.
- A future helper/test scope contract.
- A safety boundary before any code-level helper work.
- A continuation of the structured AI sketch planning chain.

Agent 53C is not:

- Implementation.
- Helper code.
- Test code.
- An API route.
- A server action.
- Image generation.
- OpenAI or provider integration.
- SQL.
- Supabase live work.
- Storage work.
- Customer-facing UI.
- Email delivery.
- CAD, a quote, an order, or production approval.

No image is generated by Agent 53C. No OpenAI, image provider, Supabase live
schema, live row, storage bucket, email provider, plugin, MCP server, Codex
setting, or third-party service is connected, inspected, installed, enabled, or
changed.

## 3. Future Pure-Helper Boundary

A future code-level helper agent may do the following only if separately
approved later and limited to pure local behavior:

- Normalize internal-only AI sketch status values.
- Verify legal status enum values.
- Reject `pending`.
- Format Hand Sketch Instruction sections from fake Design Spec data.

Agent 53C itself does not implement any helper.

## 5. Fake Fixture Strategy

All future fixtures must be fake and illustrative. They must contain no:

- Real customer names.
- Real emails.
- Real phone numbers.
- Real customer IDs.
- Real `publicReference` values.
- Live notes.
- `reviewer_note`.
- `customer_safe_note`.
- Protected reference image URLs.
- Real uploaded image URLs.
- Real provider response payloads.
- Generated image files.

Recommended fake fixture categories:

- Simple ring with unknown stone size.
- Pendant with reference-image inspiration metadata.
- Multi-stone ambiguity case.
- Unsupported material case.
- Risky exact-copy reference request case.
- Invalid status case containing `pending`.
- Missing required Design Spec section case.
- Human-follow-up-required case.
- CAD, quote, order, or production expectation-risk case.

Fixture names should make their fake status obvious, such as
`fake_ring_unknown_stone_size` or `fake_invalid_pending_status`.

## 9. Human Review Gate Preservation

Future helper tests must assert:

- Pre-generation human/admin review remains required.
- Post-generation human review remains required.
- Final approval for customer delivery remains required.
- Generation success is not approval.
- `approved_for_customer` is not gallery approval.
- No unreviewed draft is customer-visible.

- `internal_draft_not_generated`
- `draft_generated_internal_only`
- `needs_revision`
- `approved_for_customer`

`pending` is illegal, excluded, and not valid.
